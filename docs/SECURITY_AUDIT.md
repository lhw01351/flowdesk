## 2. 접근 로그에서 본 것

Tomcat `localhost_access_log` 기준 원격 주소는 대부분:

- `172.30.240.1` — WSL 입장에서 **Windows 호스트(NAT)**  
- `127.0.0.1` — 로컬 헬스체크/스크립트

즉 **외부 공격자의 공인 IP가 Tomcat 로그에 직접 안 남고**, 브릿지를 거친 트래픽이 Windows IP로 뭉쳐 보입니다.

### 탐지된 스캐너성 경로 (예시)

다수 요청이 아래처럼 **워드프레스/PHP/환경파일/라우터 기본비번**을 노리는 패턴이었습니다.

- `/.env`, `/.env.prod`, `/laravel/.env`, `/api/.env`
- `/.git/config`
- `/wp-admin`, `/wp-login.php`, 각종 `*.php`
- `/boaform/admin/formLogin?...` (공유기/IoT 기본 계정 시도)
- `/manager/html` → Tomcat Manager **403** (비활성/차단으로 보임)
- `/phpunit/.../eval-stdin.php` 등

응답은 주로 **302/404/403**. FlowDesk 로그인 성공으로 이어진 스캔 흔적은 이 점검에서 확인하지 못했습니다.

### 참고

- 로그 파일은 대략 **2026-10-20 ~ 2026-11-03** 구간이 남아 있었고, 점검 시점(11-08)에 Tomcat Java 프로세스는 **중지** 상태였습니다.
- 공인 IP별 추적이 필요하면 Windows 방화벽/라우터 로그 또는 리버스 프록시에서 `X-Forwarded-For`를 남기도록 바꿔야 합니다.

## 3. 리스닝 포트 (WSL)

| 포트 | 바인딩 | 평가 |
|------|--------|------|
| 3306 / 33060 | `127.0.0.1` | 양호 |
| 8080 (Tomcat) | 기동 시 WSL 내부 | 브릿지로 Windows에 노출될 수 있음 |
| 22 | `0.0.0.0` | WSL SSH — 불필요하면 끄거나 방화벽 제한 권장 |

---

## 4. 이번에 적용한 앱 보안 보강

1. **로그인 실패 기록** — 접속 로그 `LOGIN_FAIL`
2. **로그인 레이트 리밋** — 동일 IP 15분 내 실패 8회 → 15분 차단 (인메모리)
3. **스캐너 경로 404** — 미로그인 상태에서 `/.env` 등이 로그인 페이지로 302 되지 않도록, 알려진 앱 페이지만 로그인 리다이렉트
4. **방화벽 스크립트** — `open-firewall.ps1` 기본 **Private**만 · `close-firewall-8080.ps1` 추가

기존 유지: CSP·클릭재킹 방지·세션 HttpOnly/SameSite · DB 로그인 전용 · 시크릿 env

## 5. 운영 권고 (중요)

1. **공인 인터넷에 8080을 열지 않기**  
   - 포트포워딩 제거 · `close-firewall-8080.ps1`  
   - 필요할 때만 Private LAN 또는 VPN/터널
2. **관리자 비밀번호 교체** — 과거 공개 히스토리에 노출됐을 수 있음 → DB·MySQL 비번 변경 ([ENV.md](ENV.md))
3. **guest는 데모 전용** — 관리 권한 부여 금지
4. **Tomcat Manager** — 사용 안 하면 배포하지 않기 (현재 403 양호)
5. **정기 확인**
   ```bash
   bash /mnt/d/ispark_prj/flowdesk/scripts/_audit_access.sh
   # 또는
   grep -Eih '\.env|wp-|phpunit|boaform' ~/tomcat/logs/localhost_access_log.*.txt | tail
   ```
6. 접속 로그 화면에서 **LOGIN_FAIL** 이벤트 필터로 브루트포스 감시
